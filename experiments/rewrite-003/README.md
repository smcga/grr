# REWRITE-003 — selective memory under overlap

**Verdict: promising but incomplete.** With exact event labels and a linear shared reverb, an event's tail can be edited independently of another's. This is an oracle bookkeeping result, not source separation, an unheard breakthrough, or proof of general identity recovery. Recovering events from the mixture remains approximate. I could not listen to these WAVs.

## Listen

The generated stereo 24 kHz WAVs are eight seconds long. Two synthetic chords overlap from 0.6 to 1.6 s and share two pitches; the second ends at 2.25 s. The edit begins at **2.8 s**, after both sources are silent, and fades over 40 ms. All files use one common peak-protection gain so relative levels are preserved, not perceptual loudness matched.

- `01_unedited.wav`: both known-event reverb tails, with A and B panned separately.
- `02_selective_octave.wav`: A's surviving tail is mapped approximately an octave up; B is unchanged.
- `03_selective_erase.wav`: A fades away; B is unchanged.
- `04_selective_freeze.wav`: A cycles a captured tail fragment; B continues evolving.
- `10_selective_move.wav`, `11_selective_shorter_decay.wav`: only A's spatial position or post-edit decay changes.
- `05_onset_baseline_erase.wav`: naive separate reverb histories driven by the mixture, switching the active voice when B starts. All A input after 0.6 s is attributed to B, so erasing the first voice leaves A contamination and can affect B attribution.
- `06_mixture_recovered_erase.wav`: two spectral templates inferred from source-exclusive spans of the **mixture** produce estimated event components. Erasing estimated A leaves estimation errors. This is a favourable, known-two-source scenario with clean single-source intervals; it is not blind or general semantic separation.
- `07_source_mixture.wav` and `08_target_A_tail.wav`, `09_other_B_tail.wav`: input and ground-truth event contributions.

The synthetic IR is a fixed linear filter with sparse early reflections and a deterministic noise tail. The source event is a chord, not an identified real instrument. All sounds are generated by the code. Pitching uses a rough STFT frequency-bin remap, not a production phase vocoder; freeze is a loop with overlapping fades. Both can sound smeared, metallic, or click. No sound quality is claimed without listening.

## Mechanism and baseline

Because convolution is linear, `H(A+B)=H(A)+H(B)`: store separate contributions while treating them as members of the same acoustic field. At edit time, leave B untouched and smoothly replace only A's remaining output with a pitch-shifted, erased, looped, repanned or more rapidly decaying variant. For this **offline** experiment the full contributions are rendered in advance: it edits stored tail audio, not a full editable physical wave field or an independently flowing realtime reverb state. The retained event history is the mechanism; it is more exact than onset routing only because the true input labels are supplied.

For a mixed input, the experiment extracts two magnitude templates from labelled A-only and B-only time intervals, uses nonnegative least squares to estimate template weights at each STFT frame, masks the mixture, and reconstructs two components. Magnitudes are not additive when phases overlap. Two chords share notes, making identity ambiguous; the method is expected to leak. Templates come from the mixture rather than hidden stems, but the time intervals and number of sources are supplied manually. It is not a blind separation system.

The onset baseline uses the correct known second onset yet allocates the full mixture before/after that instant to two independent convolutions. This demonstrates one failure mode under overlap; it does not benchmark all possible event-aware or multivoice reverbs.

## Reproduce

Python 3.13 with NumPy 2.5.4, SciPy 1.18.1 and SoundFile 0.14.0; no model or GPU required. From repository root:

```powershell
python -m venv .venv-rewrite
.venv-rewrite/Scripts/python.exe -m pip install numpy==2.5.4 scipy==1.18.1 soundfile==0.14.0
.venv-rewrite/Scripts/python.exe experiments/rewrite-003/render.py --out experiments/rewrite-003/renders
.venv-rewrite/Scripts/python.exe experiments/rewrite-003/test_experiment.py
```

Use `.venv-rewrite/bin/python` on macOS/Linux. Existing matching output names are overwritten. Model and rendering dependencies are separate from the plugin build. No files are downloaded during rendering.

## Measured results on the test machine

`render.py` ran in roughly 0.35 s, including writing eleven WAV files (one run, CPU; not a realtime benchmark). Two precomputed eight-second mono float64 event tails occupy **3,072,000 bytes** together, excluding source, IR, STFT workspaces, other output buffers and Python overhead. Memory grows with duration and number of labelled events; streaming or a bounded memory model is not implemented. The test machine runs Windows x64; other platforms are untested.

Before output quantization, known A erasure residual after the crossfade is **0**, and the intended B contribution is **exactly unchanged**. This is a construction invariant for separately held arrays, not an independent perceptual measurement or evidence of separation. A synthetic 375 Hz steady tone processed through the octave operator had its strongest FFT peak at **750 Hz**; this does not prove high-quality polyphonic pitch shifting.

For source-level attribution, signal-to-error ratios for A and B were **2.08/2.20 dB** with onset allocation and **7.20/7.31 dB** with the favourable template-mask method. For tails after 2.8 s, they were **0.57/6.47 dB** for onset allocation and **5.59/11.49 dB** for template masks. These use 10 log10(reference energy/error energy), without scale optimization, and are not perceptual metrics. The template A+B sum reconstructs the mixture to approximately 226 dB numerical accuracy, but that tells us nothing about whether the assignment is correct: errors can cancel. The mask method is therefore still leaky even in this favourable case.

The render asserts finite metrics, exact zero of the oracle erased contribution after the fade, and unchanged oracle B. A separate test checks the octave tone, overlapping sources, mixture additivity and separation error. The spectral template procedure has access to manually marked single-source spans and does not address equal-pitch simultaneous notes in arbitrary mixed music. It cannot know semantic identity; two identical sources are generally unidentifiable from one mixture. No checks establish click-free audio, broad pitch fidelity, a bounded live memory system, CPU performance in a DAW, or a nonlinear shared-room solution.

## Prior art and next question

[NMF with spectral masks](https://www.isca-archive.org/interspeech_2011/grais11b_interspeech.html) and [polyphonic pitch-informed NMF](https://www.isca-archive.org/sapa_2008/virtanen08_sapa.html) are established source-separation approaches. [Spectral factorization limitations](https://pmc.ncbi.nlm.nih.gov/articles/PMC2409961/) include imperfect additive magnitude assumptions. This experiment combines known linear attribution with known spectral masking; no novelty is claimed.

Next compare recovered labels against a stronger open separation model on a purpose-built mixture, including simultaneous equal pitches and missing solo segments. For convergence, independently propagate labelled event contributions through the *same linear time-varying* ROOM-001 geometry and test superposition before making a selective change; explain that this equivalence fails with nonlinear/shared-state interactions.
